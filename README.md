# 初级工程师：五年

一个以互联网公司初级技术人员为主角的单人策略模拟游戏。设计参考《维多利亚3》的信息密度与因果链，但把"国家"换成"一家小公司的数据库"。

> **技术知识是世界运行的规则，不是游戏里的考题。**

---

## 当前状态

**v1.0.0：知识不是奖励，知识是工具。** 这一版把「先学习、后取得资格」的课程链整条拆掉：没有读条、没有考核、没有解锁，**任何技术任何时候都可以直接用**，玩家不需要先在游戏里证明自己会。游戏只负责创造一个不得不像工程师一样思考的处境，并如实算出后果。

**v1.1 进行中：修复工程工作台的机制漏洞。** 按任务书分六个阶段，本轮完成第一、第二阶段，第三~六阶段待续：

1. **部署成本与 API 校验**：建索引 / 改写查询 / 代码修复统一扣行动力与调查精力、占用发布窗口；未经实验直接上线事故概率更高（但**不设硬门槛**）；失败发布也付勘察 / 回滚成本且成本必须存档；三个 API 共用 `_wb_deploy()`，重复调用绕不过资源校验；`LabState` 把「实验记录 / 部署流水 / 公司资产」分成三种状态。
2. **公开与隐藏回归分离**：24 道编码题拆成 106 条 `public_cases`（前端可见）与 106 条 `hidden_cases`（边界条件、异常输入、更大数据规模）；`exam.validate_regression()` 后端同时跑两套，隐藏用例的输入 / 期望值 / 异常文本都不回传前端；执行环境补墙钟超时、内存峰值、递归深度与超大常量限制。

已实现：状态模型与序列化、SQLite 存档、流量、存储与 Buffer Pool、查询成本与访问路径选择、磁盘/连接池/应用层排队、动作系统（AP、现金、延迟生效）、周经济与月报（含 SLA 赔偿）、事件总线（因果链、决策事件、**重大事件持续冲击**）、技术债计息与再生、组织满意度、月度绩效、单屏 Web 界面（服务拓扑图 + 三透镜 + **工程工作台** + 技术档案 + 全开放知识库 + V3 式决策弹窗）、**W50~W100 自选评价周与只作参考的阶段性述职**、**行动点 ↔ 调查精力牵制**、结局状态机（终局只剩技术破产 / 被裁员）。

v1.0 的四条主线：

1. **拆掉资格链**：19 个行动全部去掉 `requires.tech` 门槛；`tech.unlocked` 不再作为任何前置；数值修正只由「公司资产」驱动。建错索引照样允许部署，只是零收益且写放大、磁盘占用真实上涨。
2. **工程工作台**：真实 SQLite 实验库（20 万行副本的轻量同构拷贝，可重置）→ `EXPLAIN QUERY PLAN` → 在实验库建索引试 → 部署到生产。索引有没有用由**物理判定**：首列必须命中 WHERE 谓词；`DATE(created_at)` 被改写前，建 `created_at` 索引也白建。没有交卷、没有评分、没有冷却重考。
3. **重大事件**：4 起持续事故（大屏退化 / 重复发货 / 尖峰雪崩 / 订单翻页变慢）每周冲击全局数据，拖得越久越重；只有玩家真的部署了有效设施或跑通生产回归用例才解除。事件叙述只给现象与线索，不再剧透根因；找同事咨询要花精力与预算，换来的也只是观察。
4. **三维分离**：玩家知识（跨局 profile，永久留在你脑子里）／角色履历（这局做过什么、出过什么事）／公司资产（真的部署了什么）。三者不自动转换——**你懂 Redis，不代表公司有 Redis 集群**。技术档案只记录「接触 / 实验 / 部署 / 事故」，知识库 44 张卡全部全文开放、可搜索。

「考核」只作为元理念存在：44 道题的用例库改作**生产回归用例**，玩家写出的修复跑通全部用例才部署，跑不通就继续查。v1.1 起 24 道编码题的用例拆成公开样例（`public_cases`）与隐藏回归（`hidden_cases`）：前端只看得到公开样例，后端连隐藏一起跑，只针对样例硬编码的写法会被拦下。
初始数字与设计文档一致：大屏 852ms、我的订单 123ms / 1.17 QPS、命中率 0.810、磁盘 1.60GB、接口 p95 145ms。

```powershell
py -3 app.py                  # 打开 http://127.0.0.1:5000
py -3 -m pytest -q            # 144 项测试
py -3 tools/balance.py --seeds 20 --weeks 24   # 平衡扫描
```

命令行：

```powershell
py -3 sim_cli.py new   --seed 42 --slot dev      # 新游戏
py -3 sim_cli.py act   --list --slot dev         # 本周能做什么（含不可做原因）
py -3 sim_cli.py act   add_index_user_created --slot dev
py -3 sim_cli.py sim   --weeks 8 --slot dev      # 推进 8 周
py -3 sim_cli.py events --slot dev               # 事件因果树
py -3 sim_cli.py month --slot dev                # 月报（含绩效等级）
py -3 sim_cli.py preview --slot dev              # 分查询明细
py -3 sim_cli.py export --slot dev               # 导出完整状态 JSON
```

三条已验证的因果链：

- 不加干预推进 8 周：IOPS 75% → 96%，p95 138ms → 554ms，第 9 周开始超时。
- 加对 `(user_id, created_at)` 索引：订单查询 123ms → 2.2ms，但磁盘涨到 1.69GB、大屏仍是 951ms——**一个索引只解决一个瓶颈**。
- 不处理大屏：第 2 周触发「大屏又卡了 → 老板在群里 @ 你」，主管信任 −8；同样的链每 4 周复现一次，第 4 个月现金转负。

## 一句话说清它和"编程课"的区别

玩家不是"学习索引"，而是**老板的大屏每天早上卡住，全站跟着变慢**。他花一周时间打开慢查询日志，发现一条 `WHERE DATE(created_at)=...` 的 SQL 扫了 120 万行。他去工作台把这条 SQL 放进实验库看执行计划，试着建索引、试着改写，最后才部署到生产——系统不打分，只告诉他磁盘涨了多少、p95 掉没掉。

**没有一道题，没有一分经验值，但玩家必须真的理解索引才能选对。**

## 三个设计承诺

1. **不编数字。** 生产侧用显式成本模型（结构参考 InnoDB），常数由真实 MySQL 基准校准；工作台里玩家写的 SQL 在**真实 SQLite 实验库**上执行、读 `EXPLAIN QUERY PLAN`，收益由物理判定（索引首列是否命中谓词）决定，不由「会不会」决定。模型哪里是简化，[设计文档/SIMULATION_RULES.md](设计文档/SIMULATION_RULES.md) §19 逐条列出。
2. **不给答案，也不发资格证。** 没有读条、没有考核、没有解锁、没有选择题、没有积分。游戏只给工程师真实会用的工具：监控与慢查询日志、全开放的内部知识库、SQL 实验库、代码编辑器与生产回归用例、同事与技术支持。玩家做什么都允许，系统只如实算物理后果——建错索引照样上线，只是零收益且有写放大。知识卡 44 张全部可读，但**读懂不等于公司里已经有了**。
3. **不让 AI 决定世界。** 结算 100% 由确定性代码完成；AI 只能把已有事实写成人话，且默认关闭。
